## 4. Functional requirements

| ID | Requirement | Source | Framework rule | Slice |
|----|-------------|--------|----------------|-------|
| ARG-001 | Login, logout and change password exist before any business feature | U | IDN-001 | 0 |

| ARG-003 | Password policy: one policy service, all values editable on the Password Complexity page, consistency validation, all write paths obey it | U | PWD-001..038 | 0 |
| ARG-004 | Lockout policy configurable per role, enforced on the server, tested in every configured variant | D | LCK-001..017 | 0 |
| ARG-005 | User management: create, read, update, delete, lock, unlock, reset password. Required fields: user name, e-mail, generated password. Separate capabilities per action | U | IDN-004, IDN-020..022 | 1 |
| ARG-006 | Creating a user, unlocking with reset and resetting a password sends an e-mail with temporary credentials. The plaintext is never stored after sending, never logged, never audited | U | PWD-007 | 1 |
| ARG-007 | SMTP settings page under the administration panel: host, port, TLS mode, user, secret (stored encrypted, never returned), test send | U | - | 1 |
| ARG-008 | E-mail templates tab: list of templates, whitelisted variables, preview, versions, locale. Templates: user created, password reset, unlocked, password changed, locked, password expiring (days from policy), critical alert (zero-day, zero-hour), hybrid incident, test | U | - | 1 |

## 5. Out of scope

- Counter-UAS effectors (jamming, engagement).
- Self-registration and federated sign-in (not chosen at intake).
- Real vendor integrations. The prototype uses the simulator and fictional data (`DEMO-2026-NNNN`).
